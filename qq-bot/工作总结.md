# QQ 群「AI 群友」机器人 — 工作总结

> 本文档记录从 0 到「@它能回话」的全部过程：做了什么、怎么搭的、踩了哪些坑、现在能干什么、下一步做什么。

---

## 一、项目是什么

做一个**像群友一样参与聊天**的 QQ 机器人，而不是「每条消息都回复」的烦人机器人。

核心行为：

| 场景 | 行为 |
| --- | --- |
| 被 @ / 被回复 | 100% 回复 |
| 普通群聊 | 用大模型判断「该不该插话」，再按相关性概率决定开不开口 |
| 主动插话后 | 30 秒冷却期内不再主动发言（@ 可绕过） |

技术选型（已确认）：

| 部分 | 技术 |
| --- | --- |
| QQ 接入 | NapCatQQ（OneBot v11） |
| Bot 框架 | NoneBot2 + FastAPI（反向 WebSocket，8080 端口） |
| 大模型 | DeepSeek（OpenAI 兼容接口，`deepseek-chat`） |
| 语言 | Python 3.14（直接跑通，未降级） |

```
  │
  ▼

  │
  ▼
回发到 QQ 群
```

## 七、踩坑记录与解决

1. **插件重复加载报错** `Plugin already exists: qqbot`
   - 原因：`pyproject.toml` 里同时写了 `plugins = [...]` 和 `plugin_dirs = [...]`，同一插件被加载两次。
   - 解决：删掉 `plugins` 一行，只留 `plugin_dirs` 自动发现。

2. **NapCat 下载版本问题**
   - 下了 `NapCat.Shell.Windows.Node.zip`（Framework 类），独立启动 `napcat.bat` 报 `node.exe: bad option: --no-sandbox`。
   - 原因：这个包自带的 QQNT 运行时不全（缺 `application.asar`），fork 时拿 node.exe 去带 Electron 参数。
   - 最终绕开：改为**注入本地已装的 QQ**（见第 3 条）。

3. **NapCat 找不到本地 QQ**
   - 原因：本地 QQ 是手动/绿色安装（未写进注册表），官方 `launcher.bat` 的注册表查询落空。
   - 解决：写了 `napcat\launcher-custom.bat`，直接硬编码 QQ 路径注入，绕开注册表。

4. **QQ 版本兼容提示**
   - 本地 QQ 是 `9.9.35-52892`，NapCat 内置偏移数据是 `9.9.32`，出现 `未找到对应版本的偏移数据` 警告。
   - 现状：NapCat 用「Major 版本」兼容模式跑通了，基本收发正常。若后续发现**漏收消息/漏发**，再更新 NapCat 到支持 9.9.35 的版本。

## 十、长期记忆系统（每个群友独立，不影响核心人格）

**目标**：让 AI 记住群友的长期信息（人设/事实/关系），多说话累积好感度、用不同风格说话，但**不干预蒸馏出的核心人格**。

- 核心人格（`corpus/persona/*.yaml`，只读）与「个人记忆」（SQLite，可更新）**完全分离**。
- 存储：`data/memory.db`，三张表 `users` / `user_memories` / `relationships`。
- 关系数值：`familiarity`（熟悉度）与 `affection`（好感度）分开；事件驱动增减（不是「每句 +1」），钳制在 [-100, 100]。
- 记忆提取：每个群友每 `memory.extract_every`（默认 15）条发言，跑一次异步提取，产出「记住的事实 + 用户画像 + 关系增量」。
- 回复时：`memory.get_speaker_block()` 把该群友的长期记忆注入 system prompt（最多 `top_n` 条）。

相关文件：`src/plugins/qqbot/memory_store.py` / `memory_extractor.py` / `memory.py` / `relationship.py`。

## 十一、绫地宁宁人格化（6 步蒸馏 pipeline）

用《魔女的夜宴》宁宁的台词语料，蒸馏出「带证据的人设卡 + few-shot 库」替代手写 prompt。已全部完成：

1. `build_scenes.py` — 切「场景单元」（前文 3~8 句 + 宁宁回复 + 后续 1~3 句）。
2. `classify_scenes.py` — 自动打标签（15~25 类）+ 关系阶段 + 情绪状态（全量 3544 条）。
3. `distill_persona.py` — 分模块蒸馏 4 份 YAML（personality/speech/behavior/social），每条规则带原始场景证据 ID（防脑补）。
4. `build_fewshot.py` — 选 400 组高质量 few-shot，运行时按 bigram 重叠检索 3~6 组。
5. `qq_adaptation.yaml` + `nene_persona.py` — 群友非男主 / 不自动恋爱 / 原作角色名清洗 / 极端情绪安全护栏 / should_speak 倾向。
6. `evaluate_persona.py` — 60 测试场景 5 维评分（角色一致性/语言辨识度/自然/群聊适应/反套路）。

**评测结果**：总均分 **4.58 / 5**（角色一致性 4.95、群聊适应性 5.0、自然度 4.83、语言辨识度 4.3、反套路 3.83）。已知弱点：开场「哎？」使用偏多（60 条里约 18% 以「哎？」开头），可后续在 `speech.yaml` 加「语气词换着用」约束。

数据产物：`corpus/persona/*.yaml`、`corpus/fewshot.jsonl`、`corpus/eval/`。运行时由 `config.yaml` 的 `persona.source: nene` 门控。

## 十二、更主动插话 + 主动冒泡

**问题**：AI 主要被 @ 才回，主动接话能力有限。原因是被三道闸压着——保守的插话提示词、二次概率抽签、30s 冷却。

**改动**（均为行为层，不动人格/记忆/few-shot）：

1. 删掉 `planner.py` 里的「二次抽签」概率门，直接信任模型的 `speak` 判断。
2. 插话提示词从「不要刷存在感」改为「只要有点想说的就开口」。
3. `__init__.py` 加「被点名必回」硬触发（消息里出现机器人名字即使没 @ 也回）+ 自消息跳过。
4. 新增**主动冒泡**：群里持续聊同一主题（默认 3 分钟内 ≥6 条且 ≥2 人）时，独立于普通插话找机会冒一句，有更长的冷却（默认 5 分钟一次）。

新配置（`config.yaml` 的 `behavior`）：

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `min_reply_interval` | 15 | 主动插话最小间隔（秒） |
| `bubble_interval` | 300 | 冒泡最小间隔（秒） |
| `bubble_window` | 180 | 「持续讨论」统计时间窗（秒） |
| `bubble_min_msgs` | 6 | 时间窗内至少多少条消息（且 ≥2 人）才冒泡 |

相关文件：`src/plugins/qqbot/planner.py`（`should_speak` / `should_bubble`）、`__init__.py`（`_maybe_bubble`）。

## 十三、插件化对外接口（朋友可加装功能插件）

项目**本身就是 NoneBot2 插件架构**：`pyproject.toml` 里 `plugin_dirs = ["src/plugins"]`，任何新子目录（含 `__init__.py`）都会被自动加载，无需改核心代码。

对外接入约定：

- **共享层** `src/plugins/_shared/`（下划线开头，NoneBot2 自动跳过、不当作插件加载）：对外暴露 `config` / `chat` / `chat_json` / `group_allowed`。
- **示例插件** `src/plugins/fortune/`（今日运势）：照抄即可写新插件。
- **指南** `docs/插件开发指南.md`：触发方式、发送、读配置、调 LLM、白名单、注意事项。

关键坑：**插件里不要在模块顶层 import 别的插件包**（会触发 NoneBot2 的 "not loaded as a plugin" 报错）；共享代码一律走 `_shared`。

## 十四、骰子插件（合并老插件 + 朋友的新插件）

把最初手写的简易骰子（只支持 `r1d6`）和朋友给的完整骰子插件，合并成一个功能更全的插件。

- 支持多骰子、加减修正、多组、保留高低骰：`r1d6`、`r2d8+1`、`r4d6kh3`、`r4d6kl2`。
- 触发：`on_message` + **锚定正则** `^/?r[0-9dkhkl+\- ]*$`（整条消息必须是骰子表达式，避免误伤闲聊）。
- 解析器与触发分离：`parser.py`（纯逻辑 `roll_expr`，可单测）+ `__init__.py`（触发与回发）。
- 也做了群白名单校验（`group_allowed`）。

相关文件：`src/plugins/dice/`。

## 十五、今日运势（fortune）+ 今日老婆（waifu）

两个功能插件，结构同构，都复用共享图片池 + 宁宁点评，主要差异在随机策略：

| | 今日运势 | 今日老婆 |
| --- | --- | --- |
| 随机策略 | `random.Random(f"{uid}-{date}")` **锁日期**，同人同天结果固定 | `get_random_image()` **不传种子**，每次随机，多次问可不同 |
| 触发 | `/运势` + 含「今日运势」 | `/老婆` + 含「今日老婆」「来点美图」「来张美图」 |
| 回复 | 图片 + 运势等级（分数）+ 文案 + 宁宁点评 | 图片 + 角色名（=图名）+ 宁宁点评 |

关键正确性点：

1. **确定性种子不能用 `hash()`**——它受 `PYTHONHASHSEED` 影响，每次进程重启都变，会让「同人同天运势一致」在 bot 自动重启后失效。改用 `random.Random(f"{user_id}-{date}")`，跨进程稳定。
2. **图片用 base64 发送**：`MessageSegment.image(file=path.read_bytes())`。直接传 Windows 绝对路径字符串（反斜杠 + 中文）会破坏 CQ 码解析，base64 最稳。
3. **触发词必须传 `set`**：`on_keyword({"今日运势"})` 而不是 `on_keyword("今日运势")`——NoneBot2 内部会 `keyword(*keywords)` 解包，传字符串会被拆成「今」「日」「运」「势」四个单字，导致含任意单字就误触发（比如「今天」「运气」都会中招）。这是踩过的一个隐蔽 bug。
4. **self 守卫**：`if event.user_id == event.self_id: return`，跳过机器人自己发出去的消息，避免自触发循环。

相关文件：`src/plugins/fortune/`（`fortune.py` 分档逻辑 + `fortunes.yaml` 五档文案）、`src/plugins/waifu/`。

## 十六、共享图片池 image_pool

把「发图」能力抽成共享模块，供所有插件复用（今日运势 / 今日老婆 / 以后「按情绪挑图」等）。

- `src/plugins/_shared/image_pool.py`：扫描 `素材/` 目录（`qq-bot` 的兄弟目录）。
- **每次调用现扫目录，零缓存**——往 `素材/` 里塞新图，下一次触发就直接能用，无需重启。
- `ImageInfo` dataclass：`file` / `path` / `character` / `series` / `mood` / `tags`。
- API：`get_random_image(rng=None)`、`get_image_by_character(name)`、`get_image_by_series(series)`、`get_image_by_tag(tag)`、`list_images()`。
- 角色名默认取「文件名去扩展名」；`素材/metadata.yaml` 可补充 series/mood/tags（`mood`/`tags` 暂留空，待以后按情绪挑图用）。

## 十七、热重载 + 一键启动

**痛点**：每次改代码都要手动重启。

- `run_reload.py`：用 `watchfiles` 监听 `src/`、`../corpus/`、`config.yaml`、`.env`、`pyproject.toml`、`bot.py`，检测到 `.py/.yaml/.toml/.json` 改动就自动重启进程（改完 1 秒内生效，无需手动）。
- 刻意**不监听** `data/`（记忆库每句话都写）和 `.venv/`（依赖），避免无意义频繁重启。
- `启动.bat`（qq-bot 内）：跑 `run_reload.py`。
- `一键启动.bat`（项目根目录）：`start` 拉起 NapCat + bot 两个窗口。

**坑：Windows .bat 编码**——cmd 按 GBK 读 .bat，UTF-8 会乱码、中文路径引用失败。用 Python `open(..., encoding='gbk')` 重写生成（顺带产出 CRLF）。

> 热重载只重启 bot 进程，**不碰 QQ 登录**（NapCat 是独立进程）。改 NapCat 自己的配置（`napcat/config/`）才需要手动重启 NapCat。
